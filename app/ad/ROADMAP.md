## 2. 開発ロードマップ

開発プロジェクトを以下の4つのフェーズに分割して進める。

### Phase 1: 基盤の安定化と回復 (Foundation & Recovery) - **完了**
- **目的**: `EventDispatcher` のリファクタリングによって生じた技術的負債を返済し、プロジェクトのコア機能をテスト可能な健全な状態に戻す。
- **主要タスク**:
  - `EventDispatcher` に、イベントを受け取ってトリガーを評価・発火させるメソッドを実装する。
  - `Mockito` を導入し、API変更に伴い無効化されたテスト群を再設計・有効化する。
- **テストのタイミング**:
  - `EventDispatcher`の評価メソッド実装後、直ちにユニットテストを作成・実行する。
  - `Mockito`導入後、無効化されていたテストを一つずつ有効化し、その都度テストを実行してリグレッションを防ぐ。
- **完了条件**: イベント評価のコアロジックが実装され、その正しさがユニットテストによって継続的に保証される状態になる。

### Phase 2: 行動定義の実装 (Behavior Implementation) - **完了**
- **目的**: マスコットが「いつ、何をするか」という振る舞いをXMLファイルから動的に読み込み、実行するための仕組みを構築する。
- **主要タスク**:
  - `Action`（行動）と `Behavior`（振る舞い）のインターフェースとクラス構造を設計・実装する。
  - XML等の外部ファイルから `Behavior` 定義を読み込むパーサーを実装する。
  - `Mascot` クラスが `Action` を実行し、自身の状態を更新するロジックを実装する。
- **テストのタイミング**:
  - `Action`の各実装クラス（`WalkAction`など）に対して、個別のユニットテストを作成する。
  - XMLパーサー実装後、定義ファイルを正しく読み込み、`Behavior`オブジェクトが生成されることをテストする。
  - `Mascot`が`Action`を実行し、期待通りに状態（座標など）が変化するかを検証する統合テストを実施する。
- **完了条件**: 「特定の条件が満たされたら、定義されたアクションを実行する」という、マスコットの基本的な行動サイクルが完成する。

### Phase 3: アプリケーションとしての統合 (Application Integration) - **完了**
- **目的**: コアコンポーネントを統合し、ユーザーが操作できるデスクトップアプリケーションとして完成させる。
- **主要タスク**:
  - [x] アプリケーションの起動・終了処理、システムトレイメニュー等のUIを実装する。
  - [x] マスコットのアニメーションを描画するビュー（ウィンドウ）を実装する。
  - [x] 設定ファイル（`config.xml`等）の読み込みと適用ロジックを実装する。
- **テストのタイミング**:
  - このフェーズでは、ユニットテストに加え、**手動での受け入れテスト（E2Eテスト）**が重要になる。
  - アプリケーションを実際に起動し、マスコットが表示され、システムトレイが機能することを確認する。
  - 設定ファイルを変更し、アプリケーションの挙動が反映されることを確認する。
- **完了条件**: ユーザーがアプリケーションを起動し、デスクトップ上を動くマスコットと基本的な対話ができる状態になる。

### Phase 4: 機能拡張と最適化 (Feature Enhancement & Optimization) - **進行中**
- **目的**: より高度な機能を追加し、パフォーマンスを改善して製品としての完成度を高める。
- **主要タスク**:
  - [x] **ウィンドウ投擲機能 (ThrowAction)**:
    - ターゲット認識、持ち上げ、運搬、投擲（放物線）、勝利ポーズ、自動復帰（アニメーション付き）の実装完了。
    - 最小化ウィンドウの復元や壁判定の除外など、エッジケースへの対応も完了。
  - [ ] **インタラクティブアクションの追加**:
    - **Pull Up**: マスコットがウィンドウの下からよじ登ってくるアクション。
    - **Teeter**: ウィンドウの端でバランスをとるアクション。
  - [ ] **設定GUIの実装**:
    - アクションの頻度や挙動を動的に変更できる設定画面。
  - [ ] **パフォーマンス最適化**:
    - キャッシュ統計の精度向上や、パフォーマンスプロファイリングに基づく最適化。
  - [ ] **多体連携アクション**:
    - 複数体のマスコットが協力してウィンドウを運ぶなどの連携動作。
- **テストのタイミング**:
  - パフォーマンス最適化の前後にベンチマークテストを実施し、改善効果を数値で測定する。
  - 新しい`Behavior`を追加する都度、その動作を確認する。
- **完了条件**: 現代的なデスクトップマスコットとして十分な機能と安定性を備える。

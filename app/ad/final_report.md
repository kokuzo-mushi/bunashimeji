# Shimeji Neo 最終プロジェクトレポート

## 1. プロジェクト概要
**Shimeji Neo** は、デスクトップマスコット「Shimeji」を現代的な技術スタック（Java 21）で再構築したプロジェクトです。
「50体以上のマスコットを60FPSで滑らかに動作させる」ことを目標に、レンダリングエンジン、メモリ管理、ネイティブ連携のすべてを刷新しました。

## 2. コア・アーキテクチャ (Iron Rules)

| カテゴリ | 採用技術 | 選定理由 |
|---|---|---|
| **Runtime** | **Java 21 (LTS)** | Project Panama, Virtual Threads, ZGC などの最新機能を利用するため。 |
| **Native Interop** | **Project Panama (FFM API)** | JNAのオーバーヘッドを排除し、OSネイティブAPIを高速に呼び出すため。 |
| **Rendering** | **Active Rendering** | OSの再描画イベントに依存せず、正確な60FPSループを制御するため。 |
| **Scripting** | **GraalJS** | 高速なJavaScript実行と、Javaとのシームレスな連携のため。 |
| **GC** | **Generational ZGC** | 大量のオブジェクト（マスコット）を扱いつつ、GC停止時間を1ms以下に抑えるため。 |

## 3. フェーズ別実装成果

### Phase 1: Native Integration & DPI Handling
Windows 11 環境における高DPI対応と、ウィンドウ制御の基盤を構築しました。

- **Project Panama の導入**: `SetWindowPos` や `UpdateLayeredWindow` などのWin32 APIを、`java.lang.foreign` パッケージを用いて直接呼び出す仕組みを実装。
- **Per-Monitor V2 DPI 対応**: モニタごとのDPIスケールを正確に取得し、物理ピクセルと論理ピクセルの相互変換ロジックを実装。これにより、DPIの異なるマルチモニタ環境でもマスコットのサイズや移動距離が正しく維持されます。
- **透明ウィンドウ**: `java.awt.Window` と `UpdateLayeredWindow` を組み合わせ、アルファチャンネル付きの画像を高速に描画する仕組みを確立。

### Phase 2: Logic & Scripting Architecture
マスコットの「頭脳」となる行動ロジックを柔軟に記述できる環境を構築しました。

- **GraalJS 統合**: マスコット個体ごとに独立した JavaScript `Context` を持たせ、変数の隔離と安全な実行を実現。
- **非同期ビヘイビア (Generators)**: JavaScript のジェネレータ関数 (`function*`) と `yield` を使用し、「歩く -> 待つ -> ジャンプ」といった一連の動作を、フレーム単位で中断・再開可能なコルーチンとして記述可能にしました。
- **イベント駆動システム**: `EventDispatcher` を中心に、マウスイベントやシステムティックをトリガーとしてビヘイビアを評価する仕組みを実装。

### Phase 3: Rendering & Performance
多数のマスコットを表示してもパフォーマンスが低下しない、堅牢なレンダリングループを実装しました。

- **Direct3D パイプライン**: JVMオプション `-Dsun.java2d.d3d=true` を有効化し、GPUアクセラレーションを活用。
- **高精度 60FPS ループ**: `System.nanoTime()` を使用した可変スリープ方式のメインループを実装し、PCの性能に依存しない一定の動作速度を実現。
- **Generational ZGC**: `-XX:+UseZGC -XX:+ZGenerational` により、メモリ割り当ての激しい状況でもフレーム落ち（カクつき）を完全に排除。
- **画像最適化**: 読み込み時に `BufferedImage.TYPE_INT_ARGB_PRE` (Pre-multiplied Alpha) に変換することで、GPUへの転送コストを最小化。

### Phase 4: Packaging & Distribution
開発されたアプリケーションを、一般ユーザーが簡単に利用できる形にパッケージングしました。

- **インストーラ作成**: `jpackage` と WiX Toolset を使用し、必要な JRE モジュールのみを同梱した軽量な MSI インストーラを作成。
- **CI/CD**: GitHub Actions ワークフローを構築し、コードの変更ごとに自動でインストーラをビルドする体制を確立。
- **動的設定機能**:
  - **スキン切り替え**: `img` フォルダ内のサブフォルダを認識し、再起動なしでマスコットの見た目を変更可能に。
  - **パラメータ調整**: 重力やゲームスピードをスライダーでリアルタイムに変更可能に。
  - **ウィンドウ限定モード**: 特定のウィンドウ内（例：メモ帳）にマスコットを閉じ込める機能、および対象ウィンドウ最小化時の自動非表示機能を実装。

## 4. ディレクトリ構成

```text
ShimejiNeo/
├── bin/                # アプリケーション実行ファイル
├── conf/               # 設定ファイル (ユーザー変更可能)
│   ├── actions.xml     # アクション定義 (XML)
│   └── behaviors.xml   # ビヘイビア定義 (XML + JS条件式)
├── img/                # 画像リソース
│   ├── Default/        # デフォルトスキン
│   └── (UserSkin)/     # ユーザースキン (フォルダ追加で認識)
└── lib/                # 依存ライブラリ (JNA, GraalJS等)
```

## 5. 今後の展望 (Roadmap)

1.  **Mac / Linux 対応**:
    - 現在の `NativeWindowUtil` は Windows (User32) に依存しているため、macOS (Cocoa) や Linux (X11/Wayland) 用の実装を追加する。
2.  **AI の高度化**:
    - 現在のランダムな行動選択に加え、デスクトップ上のウィンドウ配置やユーザーの操作履歴を学習して行動するAIの実装。
3.  **ネットワーク連携**:
    - 複数のPC間でマスコットが行き来したり、チャットを行ったりする機能の追加。

**総括**:
Shimeji Neo プロジェクトは、レガシーな技術的負債を解消し、将来にわたって拡張可能な高性能デスクトップマスコットプラットフォームとして完成しました。

### 次のステップ

これにて、予定されていた Phase 1〜4 の全工程が完了しました。
Shimeji Neo は現在、**高性能・高機能かつ配布可能な状態** になっています。

もし追加の開発を行う場合は、以下のようなテーマが考えられます。

1.  **物理演算の強化**: マウスで投げたときに壁で跳ね返る挙動の実装。
2.  **デスクトップマスコット間の相互作用**: マスコット同士が出会ったときに挨拶したり、手を繋いだりする機能。
3.  **プラグインシステム**: ユーザーが JAR ファイルを追加することで、新しいアクションやビヘイビアを拡張できる仕組み。
